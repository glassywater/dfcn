1. STATE, GEOMETRY, AND THE TWO TOP-LEVEL OUTPUTS

Inputs: self = RCX, param_3 = R8D, param_4 = R9D.
The second register parameter is not used to choose a text production.
Let center = integer_divide(param_3 + param_4, 2), H = native screen height.
Important fields read directly by this renderer:
  self+0x10: pointer, nonzero selects shot; zero selects throw
  self+0x28: byte, nonzero requests loading/nocking delay help
  self+0x48: byte, nonzero selects the body-part modal
  self+0x50: pointer to the target unit
  self+0x58: int32 scroll offset
  self+0x5c: byte passed to the native scrollbar renderer
Each candidate row is reached through a global vector of pointers:
  row+0x00: int16 target body-part index
  row+0x04: int32 base aim rating
  row+0x0c: uint32 flags

The cursor-mode branch starts at reference 0x881113. The first hint is
assembled at 0x88126e..0x88131e. Its key supplier call is 0x8812f1; the
loading preparation key supplier call is 0x8814d3. These key glyphs come
from native bindings rather than a hard-coded English key string.
The installed data/init/interface.txt names the relevant bindings SELECT
(Enter/Numpad Enter), A_NOCK (n), and OPTION1..OPTION20 (a..t). The binary
call operands 1, 0x164 and 0x52+visible_row_index remain the authoritative
identifiers here; a user's changed bindings may produce other glyphs.

The native std::string lengths exclude NUL and are significant at fragment
boundaries: the question is 19 bytes; the click prefix is 44; the complete
delay warning is 56; the preparation prefix is 32; the inventory suffix is
28. The click and preparation prefixes each retain their trailing space,
and the inventory suffix retains its leading space. The separate key draw
may add further visible spacing. Short inline copies and the terminating
NUL in decompiler output must not be mistaken for a shortened phrase.
Existing normalized whole-sentence translation templates can tolerate
rendered padding while retaining the separately supplied native key.

bodypart_name(unit, index):
    if index < 0:
        return "body part"
    parts = unit.body_at_0x5f8.bodyparts_at_0x00
    if index >= parts.size:
        return "body part"
    part = parts[index]
    if part.singular_names_at_0x90.empty:
        result = "body part"
        if int32(part+0x84) > 1:
            result += "s"
        return result
    if int32(part+0x84) < 2:
        return part.singular_names_at_0x90[0]
    return part.plural_names_at_0xa8[0]

This renderer inlines the body-part supplier instead of calling the general
bodypart formatter. It uses element zero of the singular or plural vector,
selected by the native count. It does not request an ordinal, invent an
ordinal prefix, or concatenate a race/caste/name with the body-part label.
Invalid indices always produce singular "body part", even if another
candidate's count is plural. Valid parts with an empty name vector produce
"body parts" only when count > 1. These two fallback words are genuine
source outputs and are included separately in the production table.

RAW BODY/BP names and per-creature INDIVIDUAL_NAME overrides supply the
non-fallback body names. The existing source extraction is in:
  ../adventure-target-panel/helper-reference-raw-display-fields.tsv
  ../adventure-target-panel/helper-classic-raw-display-fields.tsv
  ../adventure-target-panel/helper-raw-display-fields.tsv
  ../adventure-target-panel/helper-raw-display-productions.tsv
The bodypart_singular/bodypart_plural fields describe these variable leaves.
The current source vocabulary includes unusual anatomy as well as the
humanlike labels in the screenshot. Mods and generated RAW names are
variable inputs rather than additional fixed renderer strings. This aim
renderer does not itself format unit names, squad aliases, item names,
terrain captions, quests, dates, action statuses or sidebar instructions.

The source contains fourteen complete English phrases. A generic-word
match for "Normal" or an embedded match for "Imp" is not this production.
The one-point 0x8000 adjustment happens before this complete decision
chain, and can change the emitted phrase and its color. There are no
separate "Very", percent, hit-chance number, "Hard", or "Easy shot!"
productions in this function. Marker punctuation is emitted separately.

4. ALL CONDITION MARKER BRANCHES

emit_condition_markers_at(x, y, flags):
    if flags & 0x20:
        emit_at(x, y, "+", color=0x01010002)    # bright green
    elif flags & 0x40:
        emit_at(x, y, "+", color=0x01000002)    # green
    elif flags & 0x80:
        emit_at(x, y, "-", color=0x01010006)    # bright yellow
    elif flags & 0x100:
        emit_at(x, y, "-", color=0x01010004)    # bright red
    else:
        pass                                     # no +/- glyph
    if flags & 0x200:
        emit_at(x+1, y, "!", color=0x01010003)  # bright cyan

The first four flags have priority, not four independent append operations.
The exclamation mark is independent and can coexist with any selected
plus/minus branch or with no plus/minus branch. The 0x8000 difficulty
adjustment does not itself emit a marker. This renderer establishes these
bits' display effects; it does not assign prose names to their causes.
