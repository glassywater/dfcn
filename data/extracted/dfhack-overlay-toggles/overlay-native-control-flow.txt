1. Native enable and dispatch entry points

plugin_enable, RVA 0x1d5d0:
  if current plugin_is_enabled equals requested enable: return CR_OK;
  if requested enable:
    remember current window dimensions;
    CallLuaModuleFunction("plugins.overlay", "rescan", nargs=0, nresults=0);
  for each of 54 viewscreen method interposes:
    if !link.apply(requested enable): return CR_FAILURE;
  plugin_is_enabled = requested enable;
  return CR_OK.

The 54 links are 18 screens multiplied by feed, logic, and render.
Recovered screens: adopt_region, choose_game_type, choose_start_site,
dungeonmode, dwarfmode, export_region, game_cleaner, initial_prep, legends,
loadgame, new_arena, new_region, savegame, setupadventure, setupdwarfgame,
title, update_region, world.
See overlay-native-viewscreen-dispatch.tsv/json for exact RVAs and RTTI types.

plugin_shutdown, RVA 0x1e000:
  return plugin_enable(out, false).

plugin_onupdate, RVA 0x1de10:
  if width or height or df::global::init field at offset 0x3c changed:
    CallLuaModuleFunction("plugins.overlay", "reposition_widgets", 0, 0);
    remember dimensions and that init field;
  CallLuaModuleFunction("plugins.overlay", "update_hotspot_widgets", 0, 0);
  return CR_OK.
The numeric init field is left unnamed because the assembly establishes the
coordinate, not the semantic field name.

Common bridge, RVA 0x1d200:
  CallLuaModuleFunction(out, core.lua_state, "plugins.overlay", function_name,
                        supplied_nargs, supplied_nresults,
                        argument_lambda, result_lambda, true);
  native event timing bookkeeping surrounds the call.

2. Fortress-mode method hooks and their branches

render: RVA 0x1c010
  original_render(mode);
  push arguments via lambda RVA 0x15450:
    Lua argument 1 = viewscreen_dwarfmodest identity's name;
    Lua argument 2 = PushDFObject(viewscreen_dwarfmodest identity, this);
  bridge("render_viewscreen_widgets", 2, 0).
There is no plugin-specific text or toggle branch in this native render hook.

logic: RVA 0x1af30
  original_logic();
  bridge("update_viewscreen_widgets", 2, 0), using lambda RVA 0x14d90.

feed: RVA 0x199f0
  handled = false;
  if byte length between world fields at offsets 0x112390 and 0x112398 >= 8:
    original_feed(keys); return;
  push arguments via lambda RVA 0x15d00:
    viewscreen class name, PushDFObject(this),
    PushInterfaceKeys(normalize_text_keys(keys));
  bridge("feed_viewscreen_widgets", 3, 1);
  result lambda RVA 0x16920 obtains lua_toboolean(state, -1);
  if handled: markInputAsHandled();
  else: original_feed(keys).
The world fields are left unnamed for the same reason as the init field above.
This native branch gates input dispatch, not overlay text rendering.

The import table has no Screen::paintString/paintTile renderer. The recovered
render wrappers contain only original-render dispatch, argument closure setup,
the shared Lua bridge, and C++ closure/security bookkeeping. Text and toggle
branches of the overlay framework's providers are consequently in their Lua
render/widget definitions, not literal switches inside this overlay DLL.
This conclusion concerns overlay.plug.dll; independent render hooks in other
native plugins must be traced separately.

4. Lua enable, focus, visible, active and position conditions

do_enable, lines 164-193:
  config.enabled = true;
  if widget.hotspot: insert in active_hotspot_widgets;
  for every widget.viewscreens entry:
    normalize long/short viewscreen name, discard focus suffix;
    insert in active_viewscreen_widgets[normalized_name];
  invoke overlay_onenable when supplied.
do_disable removes the same entries and invokes overlay_ondisable.

matches_focus_strings, lines 479-496:
  no focus strings -> true;
  examine focus strings for current simplified viewscreen;
  accept dfhack.gui.matchFocusString(full_focus, vs);
  also accept corresponding dfhack/lua focus against current screen;
  return false if this viewscreen had focus restrictions but none matched.

_render_viewscreen_widgets, lines 563-576:
  for every enabled widget attached to the supplied viewscreen:
    require no concrete vs OR matching focus strings;
    require utils.getval(widget.visible);
    render through full-window painter when fullscreen,
    otherwise through scaled-interface painter.
  Render does not additionally require widget.active.

render_viewscreen_widgets, lines 580-587:
  _render_viewscreen_widgets(vs_name, vs);
  _render_viewscreen_widgets('all', nil);
  pending force_refresh -> request one full display refresh.

Input path, lines 520-560:
  native text-entry active -> return false;
  otherwise current-screen widgets, then 'all' widgets;
  each requires focus, active, visible, and successful onInput(keys).

OverlayWidget defaults, lines 604-615:

  fullscreen=false; hotspot=false; viewscreens={}.
Per-widget default_pos and persisted overlay.json positions can override this.
The screenshot coordinates are therefore not a fixed provider slot. All
providers able to attach to the current screen or 'all', including their
dynamic subviews and text-option branches, are relevant to the same area.

and native-display-call-sites.asm. This inventory distinguishes native drawing

text-drawing import does not imply absence of returned display text.
