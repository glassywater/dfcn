冒险模式公告提示框：原生来源与本次修改
2026-10-20

本目录是离线反编译资料，不是测试结果或游戏内显示记录。

研究映像为当前安装目录中的 Dwarf Fortress.exe：
  PE:6a70a6d9:02711000
  ImageBase = 0x140000000
完整路径、文件大小和 SHA-256 见 source-image.tsv。
所有 pe-*.asm / pe-*.c / pe-*.tsv 的 VA 均属于这个映像。
此前保存的 ELF 反编译资料仍在 ../adventure-announcement-native/，
其地址不与本目录 PE 地址混用。

原生路径

  RVA 0x7f7020：冒险操作处理，包含截图中的装备收起／拔出分支。
  RVA 0xe3c20：公告提交。保存完整字符串、公告类型和人物等元数据。
  RVA 0x684a10：说话者及可选听者包装，将完整话语提交到同一队列。
  RVA 0x8a40e0：把公告正文换行，并在每条显示行保留原报告父对象。
  RVA 0x8020c0：提示框显示；有普通居中、对话、续行、滚动、
                More／Okay 控件等分支。
  RVA 0xc65450：完整物品字段；普通物品、神器、书名、书写工具和副本。
  RVA 0x13345d0：完整身体部位字段，包括 RAW 名、序号及缺失名称回退。

提示框不是单独的“收起装备”消息框。它消费共用公告队列，具体显示内容
还受原生公告设置和当前记录状态控制。因此提取从队列及对话提交函数
反查原生调用者，不按截图中的两个英文句子筛选。
本次映像提取包含 243 个函数范围、961 个队列／对话提交点、
108457 条比较和跳转指令，以及 12244 个 switch 选择值。

文件含义

  pe-functions.tsv：本次提取的函数范围和角色；code_end_va 为右开边界。
  pe-submissions.tsv：实际解码后的队列／对话提交调用点。
  pe-calls.tsv：字段供应及其他调用边。
  pe-branches.tsv：比较、条件转移及跳转原始指令。
  pe-switches.tsv：原生选择值到实际目标块；保留字节重映射与共用目标。
  pe-literals.tsv：字符串、向量存储及立即数存储中的文本操作数。
  pe-*.asm：逐函数原始指令。
  pe-*.c：Ghidra 实际反编译输出，不是人工伪代码，也不是可编译源码。
  pe-*-regions.tsv：部分大函数的反编译区域边界。
  pe-text-productions.tsv：原生来源、完整句型、动态字段和现有译文来源。

反编译使用本机 Ghidra 12.1.2，关闭全程序自动分析；工具为
tools/extract_adventure_popup_pe.py 和 tools/DecompileAdventurePopupPE.java。
提取器读取映像，不执行游戏或翻译器。已有同一 PE 身份的来源清单提供
跳表位置；表项从本次磁盘映像重新读取，对话调用者的表项另由指令提取。
尾部跳表属于数据，不能作为游戏指令解释。

大函数不能稳定生成单个优化 C 函数时，保留各原始指令区域的实际 C。
区域边界、分析用 CALL_RETURN／无后继标记不是游戏修改。跨区域原始
跳转和全部表项仍在汇编及 TSV 中。Ghidra 的未知类型、栈变量和错误
路径警告原样保留；有歧义时以原始指令、提交点和字段调用为依据。

完整句型索引复用 ../announcement-popup-native/ 已有的构造资料，
另纳入对话专用调用者、显示控件和当前冒险公告完整语法。旧目录里的
通用字段记录按当前来源文件同步为物品、部位等字段；没有唯一原生
函数归属的共享语法保留空 owner，而不从地址区间端点推断归属。
来源记录包括共享子句和重复引用，
记录数量不等于独立句子数量。材料、物品、身体部位、人物、地点、
书名、数量、RAW 名称及用户自定义名称是动态字段，不能把这些字段
在所有存档中的无限组合假称为有限的逐句枚举。

本次修正

截图中的原生分支为：
  0x7fb91b：写入 "You strap "
  0x7fb958：调用 c65450(item, string, false, 1)，返回含冠词的完整物品名
  0x7fb970：追加 " to your "
  0x7fb9b9：调用 13345d0 的 mode 2 身体部位名称
  0x7fb9c5：部位名首字母大写
  0x7fb9eb：追加句号
  0x7fba2a：以类型 194 提交整句
拔出装备分支为 0x7fbbc9..0x7fbcd8，保留独立的物品和抓握部位字段。

1. 通用 UI 提示中的普通 {s} 字段按原生供应者改为物品 {i}、
   身体部位 {t}、人物 {n}；覆盖装备、拾取、装填、穿脱、容器及
   相关动作。两个来源清单与当前 translations.tsv 同步原地修改。
2. 普通提示框显示路径在确认原生行可见后保留完整报告及公告类型，
   复用公告日志的整句翻译入口；不再只传一段无类型的正文。
3. 物品字段先识别冠词后的完整装备名，再进入书名等其他合法分支；
   UI 的 {i} 和原生公告的 $announcement-item 使用同一入口。
4. 整句直接构造不再局限于少数以 You 开头的动作白名单；所有已有
   固定开头、字段明确的冒险公告句型都可使用同一处理路径。
   人物开头和有歧义的分隔符仍由原有完整语法处理。
5. 同伴行程抱怨的七种固定话语属于带说话者的完整公告；缺粮通知
   还必定附带农田、屠宰及采集建议。现有完整组合译文继续使用，
   没有把这些中间字面量重复添加成八条独立提示。

收起装备的目标句式为“你将{物品}绑在自己的{部位}上。”；
铜长剑和铜小盾通过原有物品词汇组合，不写截图专属替换词条。
没有改动用户自定义名称的原样显示规则。

构建与部署

运行词表已原地修改。用户随后明确要求交叉编译 Windows 版，已使用
项目现有入口 build-windows-cross.sh --deploy-project，退出码为 0。
固定 MinGW-w64 16.2.0 与 Windows SDL2 2.30.11 SDK 编译完成，
保持 C++20、-O2，不增加调试信息，也不另行生成运行数据。
Windows x64 产物保存在 build/windows-x64/，并由同一入口部署到
项目根目录的 dfcn_core.dll 和 dfhooks_dfcn.dll。游戏安装目录下的
dfcn 为本工作区的符号链接，因此使用同一份 DLL 和运行数据。
先前 Linux 本机构建因安装目录缺少 dwarfort／Dwarf_Fortress 退出 1；
本次交付的是用户指定的 Windows DLL，不包含新编译的 Linux .so。
没有操作游戏窗口、触发重载或启动／终止游戏；未观察游戏内最终效果。
