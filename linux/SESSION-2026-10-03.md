## 1. 调查结论：官方没有 Linux 预编译包

- 创意工坊和 GitHub Release 只有 **Windows x64** 运行包（`dfhooks.dll` 等），Linux 原生游戏无法使用。
- 上游说明“提供 Linux 原生适配”，但 Linux 只能从源码自己编译：
  - 入口 `build-deploy.sh` 写死了作者本机的 Python 路径
    （`$HOME/.cache/codex-runtimes/.../python3`），必须改过才能用；
  - `tools/build.py` 要求源码放在游戏目录下的 `dfcn/` 子目录中，并读取游戏的
    `dwarfort`、`data/vanilla`、`g_src/` 来重新生成数据。
- Linux 产物：游戏根目录的 `libdfhooks.so`（游戏启动时自动 `dlopen("./libdfhooks.so")`）、
  `dfcn/libdfcn_core.so`、`dfcn/data/runtime/`（配置、词表、规则）。
- Linux 下运行数据固定从 **当前工作目录下的 `dfcn/`** 读取（`src/runtime_paths.h`），
  因为核心通过 memfd 加载，无法用模块路径定位。

## 2. 用 GitHub Actions 编译

### 为什么能在 CI 上编译

- 所有生成的源码（`src/native_elf_build_bindings.inc`、`src/native_history_event_profiles_elf.inc`、
  `src/creature_vocabulary.inc`、`data/runtime/translations.tsv` 等）**都已提交在仓库中**，
  不需要游戏程序来重新生成。
- 编译时唯一缺少的是游戏自带的 `g_src/init.h`（`src/native_runtime.h` 引用）。
  它从 bay12games.com 官方免费 Linux 包 `df_53_16_linux.tar.bz2` 中只解压 `g_src/` 获得，并缓存。
- 编译参数照搬 `tools/build.py` 中 `linux` ABI 的设置（C++20、`-O2`、`-fPIC -fvisibility=hidden
  -fno-gnu-unique`、`-Wl,-z,relro,-z,now -Wl,--no-undefined -ldl`，核心另加
  `-Wl,-Bsymbolic,--version-script=src/core.exports`），直接调用 g++，不走 `build.py`。
- 先在本地 podman `ubuntu:24.04` 容器中验证编译成功（核心约 2.5 分钟），再推送。

### 新增文件（均不修改上游原有文件，减少同步冲突）

| 文件 | 作用 |
|---|---|
| `.github/scripts/build-linux.sh` | 编译 + 打包 `DFCN-Linux-x64.tar.gz`；写入 `SHA256SUMS`、`BUILD-INFO`、`INSTALL-Linux.txt` |
| `.github/workflows/linux-build.yml` | 触发、同步上游、编译、上传产物、发布 Release |
| `linux/dfcn.sh` | 本机安装／卸载／状态脚本 |
| `linux/SESSION-2026-10-03.md` | 本文档 |

### Workflow 触发方式

| 触发 | 行为 |
|---|---|
| push 到 `main`、PR | 编译，上传 Artifact（保留 90 天） |
| 手动 `workflow_dispatch` | 编译；勾选 `sync_upstream` 时先合并上游 |
| 定时（每天 03:17 UTC） | 检查上游；有新提交则合并、推送并编译，否则跳过 |
| push `v*` 标签 | 编译，并创建／更新 Release 附带运行包 |

- 同步时 merge 上游 `main`；冲突会失败报错，需本地手动处理：
  `git fetch upstream && git merge upstream/main`。
- 游戏版本从上游 README 的“当前适配版本为 **x.y**”解析，失败时回退为 `53.16`。
- actions 已升级到 Node 24 版本：`checkout@v7`、`cache@v6`、`upload-artifact@v7`。
- fork 默认禁用 Actions，已通过 API 启用。

## 3. 地址映射问题核对

上游作者提醒：Linux 与 Windows 游戏分开编译，汇编地址不同，编译能成功但可能找不到地址或映射错误。核对结果：

- Windows 与 Linux 使用**不同的地址表**：Windows 用 `src/native_pe_build_bindings.inc`，
  Linux 用 `src/native_elf_build_bindings.inc`（`src/native_reference_binding.inc` 中 `#ifndef _WIN32`）。
  Linux 编译不会用到 Windows 地址。
- Linux 地址表头部记录了生成所用的两个游戏程序，与实际文件逐一比对 SHA-256：

  | 地址表记录 | Build ID | SHA-256 | 对应文件 |
  |---|---|---|---|
  | Reference | `bcc6789e…` | `7f68fec3a8181252cc760f0c2cd11de4557b7af99d88065197b6dcae43cb88f0` | **本机 Steam 版 `dwarfort`（完全一致）** |
  | Native | `84ba59a5…` | `fde60a0273deab619db1d8363ec206952dc70ffdf4d446744e2e531a4351feee` | bay12 官网免费 Linux 53.16 `dwarfort`（完全一致） |

  两版的 `libg_src_lib.so` 相同（`4d23d3a0…`）。
- 地址数据在源码中，与编译机器无关；CI 编译与作者本机编译使用同一份地址。
- 运行时按游戏的 Build ID 选择：免费版换算为免费版地址；**其他任何程序都按 Steam 53.16 地址处理**；
  地址表中未收录的地址返回 0，不借用其他版本。
- **风险**：Steam 更新游戏后，新程序仍会按 53.16 地址处理，Reference 路径不做期望字节核对
  （`native_reference_bytes` 在非 relocated 时直接返回 true），可能出现作者所说的映射错误。
  安装脚本因此加入了版本匹配检查（见下文）。
- 编译产物尚未在游戏内实际加载验证。

## 4. 安装脚本 `linux/dfcn.sh`

直接用路径运行，不安装到 PATH 或其他全局位置。

```bash
cd /home/Kyecox/Games/dfcn
./linux/dfcn.sh install      # 下载最新产物并安装；已安装时为更新
./linux/dfcn.sh status       # 安装状态、版本匹配情况
./linux/dfcn.sh uninstall    # 卸载
```

| 选项 | 作用 |
|---|---|
| `--game DIR` | 指定游戏目录（默认从所有 Steam 库的 `libraryfolders.vdf` 中查找） |
| `--file PATH` | 使用本地 `.tar.gz` 或产物 `.zip`，不联网 |
| `--run ID` | 安装指定 Actions 运行的产物（默认 `main` 分支最新一次） |
| `--repo OWNER/NAME` | 产物来源仓库（默认 `glassywater/dfcn`） |
| `-y` | 跳过确认（版本不匹配时仍会要求确认） |

行为要点：

- 通过 `gh api` 下载 Artifact（需要 `gh` 已登录），校验 `SHA256SUMS`；临时文件在 `mktemp -d`，退出自动删除。
- **版本检查**：比对本机 `dwarfort` 的 SHA-256 与 `BUILD-INFO` 的 `supported_dwarfort_sha256`；
  不匹配时警告并强制确认。
- **更新时保留**：`config.ini`（新版默认配置另存为 `config.ini.new`）、`dfcn.log`、
  `data/extracted/`（Ctrl+F9 导出）、`untranslated.tsv`、自放字体 `font.ttf/otf/ttc`。
- **外来加载器**：根目录已有非 DFCN 的 `libdfhooks.so`（如 DFHack）时备份为
  `libdfhooks.so.dfcn-backup`，卸载时恢复。
- 安装记录写在 `dfcn/.dfcn-install`（来源、时间、加载器哈希、备份名）。
- 安全限制：游戏运行中（`pgrep -x dwarfort`）拒绝操作；不认识的 `dfcn/` 或他人加载器不删除；
  替换 `dfcn/` 失败时回滚。

测试（在 `/tmp` 模拟游戏目录，`dwarfort` 软链接到真实 Steam 程序）：

| 场景 | 结果 |
|---|---|
| 首次安装（真实 Steam `dwarfort`） | 成功，“游戏程序与汉化地址表匹配” |
| 更新 | 保留了改过的 config、日志、导出数据，生成 `config.ini.new` |
| 卸载 | 只剩 `dwarfort` |
| 已有外来 `libdfhooks.so` | 安装时备份，卸载后原样恢复 |
| 伪造 `dwarfort`（模拟游戏更新） | 警告并要求确认，选否则退出、不改动 |
| 已存在非 DFCN 的 `dfcn/` 目录 | 拒绝安装 |

## 5. 游戏内使用

| 按键 | 作用 |
|---|---|
| Shift+F10 | 开启／关闭汉化；重新开启时加载最新核心、配置与词表 |
| Ctrl+Shift+F10 | 强制重新读取配置与词表 |
| Shift+F9 | ASCII／图形模式切换 |
| Ctrl+F9 | 导出当前画面与漏译文本到 `dfcn/data/extracted/dumps/` |

- 配置：`dfcn/data/runtime/config.ini`（`enabled`、`font`、`font_scale`、`font_pixels` 等）。
- 字体：Linux 由 fontconfig 自动选择简体中文字体；也可放置 `dfcn/data/runtime/font.ttf`。
- 日志：`dfcn/dfcn.log`，无法加载或出错时先看这里。
